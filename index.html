Session 1 Part B: Numbers, Sets & Expressions

Classification of real number systems, mathematical expressions, variables, and constants.

Number Sets Taxonomy

Natural Numbers (ℕ): {1, 2, 3, 4, ...}
Integers (ℤ): {..., -2, -1, 0, 1, 2, ...}
Rational Numbers (ℚ): Numbers expressed as p/q (q ≠ 0).
Real Numbers (ℝ): All rational and irrational values (π, √2).

Expressions vs Equations

An Expression is a mathematical phrase combining variables, numbers, and operators without an equals sign (e.g., 3x + 5).

An Equation states that two expressions are strictly equal using an equals sign (e.g., 3x + 5 = 20).

Session 1 Part E: Exponents & Laws of Indices

Rules governing exponents, powers, negative indices, and zero exponents.

Essential Index Laws

• Multiplication: am × an = am+n
• Division: am ÷ an = am-n
• Power of Power: (am)n = am×n
• Zero Index: a0 = 1 (a ≠ 0)
• Negative Index: a-n = 1 / an

Computing Application

Powers of 2 define computer architecture limits:

• 28 = 256 (1 Byte max states)
• 210 = 1,024 (1 Kibibyte / KiB)
• 216 = 65,536 (16-bit addressing)
• 232 = 4,294,967,296 (4 GB RAM limit)

Session 2 Part A: The Hexadecimal Base (Base 16)

Base 16 positional system, digits 0-9 and A-F, succinct memory representation, and 4-bit binary nibble conversions.

Hexadecimal Digits & Memory Representation

Hexadecimal (Base 16) uses digits 0–9 and letters A–F to represent values 10 through 15:

• A16 = 1010 = 10102
• B16 = 1110 = 10112
• C16 = 1210 = 11002
• D16 = 1310 = 11012
• E16 = 1410 = 11102
• F16 = 1510 = 11112

Why Hexadecimal? Hex represents memory contents concisely: each hex digit equals exactly 4 binary bits (1 nibble). For example, F16 instantly means 4 consecutive switches turned ON (11112).

Session 2 Part B: Welcome to Boolean Logic — Propositions

From human decision-making to binary states, definition of propositions, truth values, and Boolean variables.

What is a Proposition?

Definition: A proposition is a statement that has a truth value that is either strictly True (T / 1) or False (F / 0).
Valid Propositions:
  • "Paris is the capital of France" (Truth value: True)
  • "2 + 2 = 5" (Truth value: False)
  • "The temperature is above 22°C" (True or False depending on state)
NOT Propositions:
  • Questions ("Is it raining?")
  • Commands / Instructions ("Turn off the heating!")

Boolean Variables

Rather than writing full verbal sentences repeatedly, we represent propositions succinctly using letters (typically p, q, r, s).

• p = 'I am in my room'
• p = T (Proposition p is True)
• p = F (Proposition p is False)

Boolean variables allow us to construct generic programming rules (e.g. "If p is True, then turn on the light") without needing to hardcode specific physical conditions.

Session 2 Part C: Compound Propositions & Truth Tables

Combining atomic propositions using logical operators, and standard truth table structure.

Atomic vs. Compound

Atomic Proposition: A single proposition represented by one Boolean variable (e.g. p = 'I am awake').
Compound Proposition: Created by connecting atomic propositions with logical operators. For example, p ∧ q represents "I am in my room AND I am awake".

Session 3 Part A: Evaluating Compound Propositions

Using truth table place markers to evaluate truth values of concrete compound statements.

Are 'true' and 'false' Statements?

Yes! 'true' is a statement whose truth value is strictly True (T), and 'false' is a statement whose truth value is strictly False (F).

• 'true' = T
• 'false' = F

Because T and F are propositions, they can be combined directly with Boolean operators to create compound expressions like T ∧ F or F ⊕ F.

Truth Tables as Place Markers

When evaluating expressions like F ∧ T, treat variables p and q in the standard truth table as positional place markers:

  • • p = Place marker for expression on the LEFT of operator
  • • q = Place marker for expression on the RIGHT of operator

Evaluation Walkthrough: q ➔ p when p = T and q = F

1. Substitute variables: Replace p with T and q with F:
q ➔ p ⟹ F ➔ T
2. Look up row in Conditional Truth Table where:
Left (Antecedent) = F, Right (Consequent) = T (Row 4)
Result: F ➔ T = T

CRITICAL RULE: Right-to-Left Precedence for Equal Operators

When Boolean operators in a proposition have the same precedence level (or the exact same operator repeated) and there are no parentheses to determine order (e.g. T ∧ F ∧ T or F ↔ T), the precedence is evaluated FROM RIGHT TO LEFT.

(Note: This is the exact OPPOSITE direction to standard arithmetic math expressions which evaluate left-to-right!)

Stepwise Reduction Trace: ~((T ∧ F) ➔ ~T) ∨ F

Step 1: Find inner brackets (T ∧ F) ➔ Replace with F
Expression: ~(F ➔ ~T) ∨ F
Step 2: Inside brackets, evaluate negation ~T ➔ Replace with F
Expression: ~(F ➔ F) ∨ F
Step 3: Evaluate conditional inside brackets (F ➔ F) ➔ Replace with T
Expression: ~T ∨ F
Step 4: Evaluate outer negation ~T ➔ Replace with F
Expression: F ∨ F
Final: F ∨ F = F
